文字采用已知歌词的 medium/int8 两组上下文音频窗口对齐，结合实际音乐反复核对段落起点；伴奏使用独立的音乐对应路径。图片通过横排 OCR、简谱旋律与实际音频的匹配建立时间轴，分别使用音符横向位置和节奏符号两组模板核对谱行边界，并检查实际反复次数。普通语音转写错误较多的候选不直接启用；模板冲突、区域缺失或音乐对应不足的曲目留待修订。

按歌词字数估计的取样窗口偏离实际副歌时，可在 `sync-window-estimate-profiles.json` 中指定上下文取样位置，绑定原文、全部录音哈希、参考录音及完整阅读顺序。配置仅选择待识别的音频片段；实际换句时间仍由原有两个声学窗口及实测音乐反复核对，其他录音仍须独立对应。取样位置变化后不得复用旧配置的已通过窗口；参考曲调估计不当作已核对的谱面分界或最终时间。

中文原文将一轮音乐分成相邻多个段落、并完整重复相同歌词时，可在同一取样配置中显式填写 `sourceCycle: {version: 1, versesPerCycle: 2, reason: "…"}`。只按该数量依次合并相邻原文段落作音乐循环检测，须至少两轮、整除全部段落，且每轮全部阅读区域的歌词须与第一轮逐项相同；配置不能指定秒数或自选分组。原文、阅读区域和完整演唱顺序不变，检测仍使用原始完整录音，保留音乐相似度、双窗口声学、首词时长、起点差和相位检查；未配置歌曲沿用原分段，其他音轨仍独立做音乐对应。

同一行的明确标签（如 `副歌：哈利路亚`、`[Chorus] Hallelujah`）只在识别输入中去掉标签，避免把“副歌”当成演唱首词；原文、显示行号及阅读区域不变。普通歌词中没有标签分隔符的词语保持完整。

正文末尾独占一行的 `（重复一次）` 或 `(重复一次)` 作为全曲反复指示处理：复用已有阅读区域，按全部原段落再唱一遍建立待核对顺序，不创建包含指示语的歌词区域。原文及显示行号保持不变；实际录音仍须通过音乐反复和逐个起点的声学检查，不能由这条指示直接生成时间点。文字时间轴回到上方原文时标记为 `return`，供播放器执行反复跳转。

已知歌词流程的声学首词须有有效时长；即使后面多个词已经对齐，零时长首词也不能确认换句起点或由音乐相位补成。复核版本更新后会重新检查旧缓存，不沿用旧版的通过状态。

已绑定素材及完整顺序的取样配置可显式启用 `extendedContext.version: 1`。原有两个窗口未确认的后续起点，另用固定的前 8／后 18 秒、前 10／后 16 秒两个上下文复核。首词须有有效时长，至少两组不同窗口的起点相差不超过 0.5 秒；所有彼此支持的结果须构成一个跨度不超过 1 秒、内部相邻差不超过 0.5 秒的时间簇，分离的两簇不能直接确认。音乐相位仍须由至少两个已确认的声学起点建立，并保留原有相似度、相位及实际换句顺序检查。已通过的起点不额外取样，首个阅读位置仍由后续实测乐段相位确认；缓存绑定补充窗口版本，旧的通过状态需按版本 3 重新核对。

实际演唱包含额外副歌或末句反复的文字曲目，可在 `sync-text-transcript-profiles.json` 中逐个对应整曲转写片段与原有阅读区域。所有片段、全部正文区域均须覆盖；重复末句只能引用原区域中的正文子串，每块仍须有至少 60% 的逐字转写对应，并通过原有双窗口起点核对。配置同时绑定歌词、录音及整曲转写哈希，原始歌词保持不变；通过 `align-image-transcript-sync.py --cache sync-drafts/bulk --songs <编号…>` 生成。

正文分界跨越转写片段时，可统一使用 `wordRange: [起始词序号, 结束词序号]`，按全曲清理后的有效词语编号，左含右不含。所有词语须且只能分配一次，不能混用片段编号；非歌词尾语须按完整原片段逐项排除，无有效词语的片段也须说明。词语范围只确定对应的原文及转写词区间，每块仍须通过逐字覆盖和原有双窗口声学核对。

录音未演唱的印刷段落须在 `unsungRegions` 中逐项绑定原文并说明实际演唱顺序。未标明的正文区域不能漏过，已演唱的区域也不能列入未演唱清单；全部实际转写片段仍须对应正文或明确核对的非歌词尾语。未演唱的原文保留在页面上，滚动只跟随录音中实际唱出的段落。

首句在两组已知歌词窗口都夹到左边缘时，可显式启用 `freeInitialPrefix.version: 1`。程序先确认全部后续起点，再用两组原音频窗口自由转写，不提供歌词提示，并固定模型与词表哈希。两个窗口都须逐字且唯一识别正文开头十个中文字符，或至少四个、十字母的英文词语；实际首词须有正时长及概率依据，词尾与原有声学窗口相符，起点及词尾分别在 0.5 秒内一致，且接续后续歌词顺序。此模式仅处理首句的窗口边缘问题，不改变其他起点的核对限值。

普通文字转写流程的首句配置另存于 `sync-transcript-prefix-profiles.json`，同样绑定正文及录音哈希；`align-transcript-sync.py` 仅对明确列出的曲目启用上述复核，其他流程保持原有限值。

文字播放器从播放开始就显示第一个阅读区域。`sync-initial-reading-profiles.json` 可将这一位置显式记为 0 秒首屏，标注 `lyricOnsetMeasured: false`，不声称测得首个唱词的起唱时刻。配置绑定原文、全部录音、完整转写哈希及实际阅读顺序，每个正文区域仍须有至少 60% 的逐字转写对应；后续换句完整保留原有双窗口、延音与争议时间簇检查。其他录音只对应后续实测换句，首屏各自从 0 秒显示；现有文本及已发布数据保持不变。此项与首词实测配置分别使用，通过 `align-transcript-sync.py` 重建。

图片 OCR 的倾斜校正只服务于识别，阅读区域已映射回原图坐标。简谱行内同一组音符下方可能印有多段歌词，区域引用按各段及副歌的顺序建立。为完整预读下一歌词行，这批聚焦歌词行的 JPG 区域使用 `previewFraction: 1`；原先聚焦完整谱行的试点数据保持原设置。

对于缺少完全对应外部曲调参考的简谱，另可逐小节复核原图，记录音级和四分音符拍数。`sync_batch_printed_midi.py` 从绑定原图哈希的表格重建固定哈希的单旋律分析 MIDI；它只能用于 `symbolic-melody-and-optical` 模式，不能把合成的和声当作独立证据。所有谱行须先通过完整音符序列与唯一首音核对，再在每个实际录音、每段独立比较此旋律和原图光学节奏：成本各不超过 0.35、调性区分至少 0.06、各起点相差不超过 0.5 秒，并覆盖完整乐段、保持反复相位一致。时间点仍来自实际录音匹配；拍数和固定速度只用于描述乐谱，不用于直接计算滚动时间。

已核对同曲的完整录音参考可用前两次实际演奏分别定位目标歌曲每个阅读区域，允许目标与参考的段数不同；所有区域都须通过两个参考各自的成本、调性、跨度及起点一致性检查。已发布参考优先读取已提交的复核记录，并重新检查素材与音轨哈希，避免临时缓存丢失使证据不可用。MIDI 模板的采样时间按毫秒比较，保留包含边界的 0.5 秒限值，避免 Float32 误差把实际相差 0.5 秒的起点误判为超限。

文字曲目也可使用已核对的公开简谱作为独立节奏参考。`opticalReference` 固定原谱、渲染图片及光学音符的哈希，显式记录拍号排除范围和正文阅读区域首音；完整音符序列及每个首音都必须与 MIDI 对应唯一。`prepare-score-reference.py --cache sync-drafts/bulk --songs <编号…>` 可重建并校验参考，需配置中的 Playwright 版本及其 Chromium，另需批处理 OCR 依赖。随后运行 `midi-sync.py`，逐录音、逐段、逐阅读区域比较 MIDI 旋律与原谱光学节奏，保留图片模式的全部成本、调性、0.5 秒、完整跨度和反复相位检查。和声仅保留为诊断；未通过的录音不能由另一版代替，也不以谱面拍数直接计算时间。检索候选不能借此绕过原有更严格的录音检查。

英文简谱的版面无法由中文歌词行检测可靠确定时，可在同样固定哈希的 `opticalReference` 中显式记录 `reviewedSystems`：逐行目视核对原始图片的音符范围及歌词上缘，并绑定 `noteExtractorVersion: 4`。像素范围必须在图内、依次排列且不重叠；提取缓存同时绑定这些范围，范围变化后必须重新识别音符和节奏。该配置只确定采样位置，不提供音符或时间答案；完整音高、阅读分界及每个实际录音的独立匹配检查保持不变。中文歌词内容和段落结构仍从原歌本单独核对，同曲英文改词只用于旋律参考。

小字号参考可用 `render.deviceScaleFactor: 2` 从矢量原谱重新渲染，以提高节奏符号的像素测量精度。渲染器支持 1 倍和 2 倍像素密度，缺省为 1 倍；每份参考的图片哈希、版面坐标、光学音符及节奏哈希均绑定其实际密度，重建时全部重新校验。

部分录音的实际段落节奏和反复估计存在漂移，可在已核对的原谱配置中显式启用 `fullPerformanceCheck.version: 1`。至少三个完整乐段先逐段通过和声、旋律检查，再将完整参考按已核对的演奏顺序拼接，另外定位整曲的和声、旋律路径。各局部及整曲路径均保留成本 0.35、调性区分 0.08／0.06、完整跨度 75%～125% 的限制；每个阅读区域的四条起点估计任意两条都须相差不超过 0.5 秒，且顺序和相邻实际乐段跨度一致。最终起点取实测路径均值；这一模式不修正到统一反复相位，也不能用于仅由音频检索提出的候选。

主歌、回应段及末句反复构成非均匀结构时，可在 `sync-sectional-midi-profiles.json` 明确绑定原文、全部录音、原始 MIDI、旋律声部、原谱图片及完整乐段顺序。`sectional-midi-sync.py --cache sync-drafts/bulk --songs <编号…> --prepare` 可下载固定哈希参考并重建识别结果；从原 MIDI 的明确拍数范围重组分析参考，保留原有音高、时值及和声，不按谱面时长生成滚动时间。原图版面和识别音符另有哈希，提取版本 5 显式规范全角数字；已目视核对的同音连线只合并相邻同音音头，三连音须逐组引用原谱连续三个音符。旧提取版本及已发布数据不变。

原谱长音跨到下一物理谱行时，可在 `opticalReference.crossSystemTies` 明确声明 `version: 1`、按顺序排列的相邻谱行对 `boundaries` 和目视核对说明 `reason`。只允许前一行末音与下一行首音的音级及临时升降号完全相同，且同一印刷乐段必须连续包含连线两端；休止、异音、跳行、重复声明、截断或从延续音头开始均拒绝。合并只累加原有时值，不新增起音、不改原谱图片或任何录音匹配阈值；未声明的既有谱本保留原行为。

此流程至少覆盖三个正文阅读区域，完整原谱音高序列与所有首音须在 MIDI 中对应唯一；参考录音分别通过整曲 MIDI 旋律、整曲图片节奏、逐区域 MIDI 旋律及逐区域图片节奏四条路径。每条路径保留成本 0.35、调性区分 0.06、跨度 75%～125% 的限制，每个阅读起点的四条估计任意两条相差不超过 0.5 秒，整曲和逐区域调性一致，录音首尾不得遗留可容纳完整乐段的范围。取样时长和前奏估计只限定搜索范围；其他录音仍须通过原有 chroma-DTW 对应及每个换句的局部成本检查。原始歌词、空行、图片及音频不改写。

分段参考也可显式使用 `midiReference.origin.kind: printed-numbered-score`，从目视核对的原谱音级与四分音符拍数重建原始分析 MIDI。原图须先通过哈希检查，人工表格绑定同一原图，重建字节还须符合固定 MIDI 哈希；随后仍完整提取并核对独立光学音符及全部实测路径。第一个阅读区域可覆盖器乐前奏和首句，配置须明确说明这一阅读位置不表示首句起唱。

原谱包含临时升降号时，可在同一人工拍数表的 `accidentals` 版本 1 中逐音记录 `-1`、`0`、`1` 半音偏移，并说明目视核对的位置；每行偏移数必须与原谱音头一一对应，休止不能升降，自然音或还原音明确填 `0`。这只用于重建已绑定原图的旋律，不能修改拍数或跳过独立光学音序、调性、成本和实测起点检查。

多页图片原谱可用 `image.stackImages` 版本 1 固定每张原图的网址、SHA-256、页序及 Pillow 版本。程序只将完整原图依次向下排列，保留原始大小，较窄页右侧补白；不裁剪、缩放或修补谱面。每次复用也须重新检查全部原页哈希，重建后的 PNG 另须通过固定哈希，之后再提取音符与节奏。单页及 PDF 原谱保留各自的既有流程。

相邻乐句高度近似时，可显式启用 `localOnsetWindow: {version: 1, fraction: 0.4}`。整曲匹配保持原范围；逐段路径的首个查询帧只能在整曲结果提供的上下文中搜索，范围固定为该段实测跨度的正负 40%。这只防止局部查询误认相邻乐句，实际起点仍来自音频路径，原有成本、调性、完整跨度及四路径 0.5 秒检查不变。未配置的曲目保留原搜索方式。

正文之间存在器乐过门时，可在 `readingSectionReview` 中以版本 1 将每个原文阅读区域绑定到连续、完整的实际乐段。整曲 MIDI 和光学路径仍包括全部乐段，所有音乐分界仍须通过完整音符序列的唯一对应；`instrumentalSections` 必须逐项列明没有另设阅读区域的器乐部分，不能遗漏、重复或打乱正文。每个正文区域的局部核对只包含其已声明的演唱乐段，跨度取自两条整曲实测路径中的该组起止位置；首屏也可包含明确说明的器乐前奏。全部正文起点仍要求整曲和局部四路径互差不超过 0.5 秒，成本、调性、跨度及首尾检查保持不变。内部音乐分界不另生成滚动点；原始歌词、空行和未启用分组的既有数据保持不变。

同曲录音的配器或速度不同、不能通过跨录音对应时，可在 `independentRecordings` 逐项绑定现有非参考音轨的文件名、SHA-256 和整曲取样范围。每版分别使用同一份完整原谱、MIDI、正文及乐段顺序，独立运行整曲和逐区域四路径复核；调性、成本、跨度、0.5秒、首尾及所有已声明尾奏变体检查全部保留。基础附加配置只能改变搜索范围；末段再奏按下面的限制单独复核，不能改动正文结构。任何指定录音失败都会阻止导出，不能回退到复用另一版的时间点；全部指定录音通过后，才把各自实测的完整时间轴交给播放器。未指定音轨保留原有跨录音对应流程。

某版录音在正文后再次演奏末个阅读区域时，可在该音轨的 `endingReadingRepeat` 版本 1 中明确绑定末区域、同一个末段原谱乐段、原 MIDI 拍数范围、派生 MIDI 文件和哈希，并说明实际再奏。程序只能在完整正文参考尾部追加该段一次，所有正文拍数、起音和阅读分界保持不变，末区域持续显示；配置不能替换中间乐段或覆盖原参考文件，也不能叠加转调、器乐分组或尾奏变体策略。整曲光学音序、全部唯一阅读起点以及完整和局部四路径均须针对追加后的实际结构重新通过，任何失败均阻止导出。

参考录音在末个阅读区域继续反复完整副歌或末句时，可显式填写 `referenceEndingSequence` 版本 1，逐段绑定原谱乐句、原 MIDI 拍数和完整结尾的文件哈希。每个追加乐句必须是末区域原谱坐标中唯一、连续的至少五个音头；程序只在共同正文后追加，不能改动正文、阅读分界或原参考文件。其他录音仍单独使用共同正文及自身已声明的结尾，不能沿用参考录音的附加乐句。参考录音的完整结构重新通过全部音序、起点、调性、成本、跨度及首尾检查，末区域保持显示，不为同一段反复新增移动。

同一完整歌段分成多个阅读区域、并在实际录音中反复演奏时，可显式启用 `sourceVerseContext` 版本 1 并说明结构。歌段分组只能从当前原文的全部段落依次导出，各段阅读区域数量必须一致；配置不能自行填写或遗漏分组，也不能与前一区域策略叠加。局部核对保留至多一个完整前段和本段已唱部分，当前区域仍单独标记，全部四路径的成本、调性、跨度及起点差限制不变。首尾按完整歌段的实测跨度保留 75% 检查，同时逐录音独立检索音乐反复，要求每段的每个阅读起点相对第一段的相位差不超过 0.5 秒；所有尾奏变体也须通过同样核对。缺少反复证据、错段或局部路径失败均阻止导出，不使用谱面时长推算滚动点。

正文至少三段、末个阅读区域又完整重复一次同一副歌时，可显式填写 `sourceVerseMusicRange` 版本 1、`endBeforeSection` 及结构说明。末阅读分组只能含原副歌与追加副歌两个连续乐段；除声乐休止外，两段原谱音头、音高及节奏必须完全相同，不能排除正文、替换末句或叠加其他结尾变体。比较范围从首个正文到追加副歌前，两端均由整曲 MIDI 和光学路径独立测得并须互差不超过 0.5 秒，配置不能填写秒数。音乐反复仍从范围内的原始音频独立检索，相似度 0.60、各段对应 0.55 及全部阅读相位 0.5 秒限制保持不变；末段无需包含前两段之后的相同间奏，但每段实际共有比较窗口至少覆盖检测周期的 75%。范围外的追加副歌及器乐尾奏仍纳入完整谱面及四路径核对，不能用截短音频替代整曲验证。

同音弱起或近似乐句需要更多上下文时，可显式启用 `previousReadingContext: {version: 1}`。局部查询固定加入一个完整前一区域，以及两个区域之间已经声明的器乐部分；目标阅读区域仍单独标记，取其自身音频路径起点，不使用上下文首帧作为滚动时间。完整及局部路径仍逐个核对每个正文位置，保持成本0.35、调性区分0.06、完整查询跨度75%至125%和四路径0.5秒限制。上下文不能改为任意长度；首个阅读区域及未配置曲目使用原有查询方式，首尾和实际阅读跨度检查不变。

长前奏歌曲的原文歌段含多个阅读区域、末段又多唱部分原文时，可显式启用 `sourceVerseEdgeReview` 版本 1 并说明结构。仅首尾遗漏检查改按当前原文全部歌段自动分组，允许末段阅读区域数量不同；配置不能填写分组、时间或遗漏比例，也不能与 `sourceVerseContext` 叠加。全部阅读区域仍分别通过整曲及局部四路径，前后剩余音频若可容纳最短完整歌段实测跨度的 75% 仍拒绝导出；不会因单句阅读区域较短而把已核对的前奏误判成遗漏正文。未启用曲目的行为保持不变。

录音中存在已经独立核对的转调时，可分别在 MIDI 重组配置中使用 `transposeSections`、在光学顺序中使用 `transposeParts`，逐项填写完整乐段的整数半音，且必须附版本 1 的 `transpositionReview` 说明。只整体移调该段全部声部，保持音程、原始拍数、音符时值及成对的起止事件；不能单独修补音符。完整音符序列及所有阅读分界仍须唯一对应，实际音频的调性、成本、跨度与四路径起点检查不变。相同速度的重复 MIDI 标记合并为一个原始速度；存在不同速度仍拒绝该重组模式。原谱若来自 PDF，`image.pdfSource` 绑定原文件、网址和 SHA-256，`renderPdf` 绑定页码、倍率以及 pypdfium2/PDFium 版本；`--prepare` 从原 PDF 重新渲染并校验图片哈希后才更新缓存。

器乐尾奏编配不能唯一确认时，可在明确绑定末个区域的 `instrumentalOutroReview` 中说明，并逐项列出 `instrumentalOutroAlternatives`。每个变体仅替换最后的器乐参考片段，不能替换正文分界；所有参考均须重新通过完整音符、整曲及逐段路径检查，且所有正文时间轴任意两条都须在 0.5 秒内一致。通过后保留主参考的实测时间，不从变体中挑选一条可通过的结果。

已核对英文简谱的文字歌曲，也可对指定录音显式启用 `completeOpticalCheck.version: 1`，配置绑定录音文件名及 SHA-256。至少三个完整乐段分别由整曲 MIDI 主旋律和原谱图片光学节奏定位，再按实测乐段跨度重新逐段定位两组模板。四条路径保留成本 0.35、调性区分 0.06、跨度 75%～125% 的限制，所有区域的起点须任意两条相差不超过 0.5 秒，整曲与逐段调性相符，首尾也不得遗留可容纳完整乐段的音频。该模式按实际演奏速度测量位置；未指定的其他录音仍使用原有逐段及反复相位核对。

完整歌段之间存在器乐过门时，可显式填写 `vocalInterludes: {version: 1, afterVerses: [{verse: 1, quarterBeats: 20}], reason: "…"}`。歌段编号从 1 开始，位置只能从当前原文完整段落的边界自动取得；须按顺序逐项声明，不能指定音频秒数、段内位置、前奏或尾奏，也不能遗漏正文。每处使用 1 至 64 个整数四分音符拍数描述分析上下文，程序按照原 MIDI 的总拍数与采样权重换算，在 MIDI 和光学查询中同时追加不发声音符；原始 MIDI、谱面音头、正文阅读区域及其顺序保持完整。这些是已核对器乐过门的声乐休止查询描述，不声称它们印在原谱中。休止仍承担既有匹配成本，整曲和局部四路径、调性、0.35 成本、完整跨度及 0.5 秒起点差检查全部保留，每个声明的录音分别复核。该配置不能叠加器乐乐段分组、完整歌段音乐相位、尾奏变体或另行追加结尾策略；未配置的歌曲沿用原有查询。证据中的 `vocalInterludes` 记录自动取得的原文分组、休止位置及模板权重，最终换句时间仍来自完整原始录音。

完整乐曲原谱模式可显式配置 `language: "en"` 复核英文歌词；未配置时继续使用中文。语言只决定原文解析和起句字符规范化，仍逐项绑定当前歌词哈希、全部录音、完整阅读区域与至少四个有效起句字符；不能省略或重排原文区域，音频的四路径成本、调性、跨度、起点差、顺序和首尾检查不变。

英文原文若用空行逐行分段，可配置 `musicalVerseEdges: {version: 1, paragraphsPerVerse: [6, 5, 7], lastVerseRepeatsFinalReading: true, reason: "…"}`，仅用于首尾是否遗漏完整诗节的检查。每个计数须为至少 3 的整数，连续覆盖全部单阅读区域的原文段落；首节的全部发声音高及独立拍数必须与完整印刷原谱逐项一致，各后续诗节在 MIDI 与光学模板中也须完整一致。末节可显式多唱一次相同的原有末阅读区域，除此之外不允许缺音、改音、改时值、重排或附加尾句。声乐休止只能放在这些完整诗节之间；该配置不能叠加其他原文分组、器乐乐段分组或结尾策略。原阅读区域、全部音频查询和逐区域四路径检查不变，分组中不接受秒数或手填起点。

公开原谱为 SVG 时，`image.svgSource` 绑定原始文件、网址及 SHA-256；原站要求来源页时可显式固定 `referer`，下载仍逐字节校验原始哈希。`renderSvg` 绑定版本 1、1 至 4 倍的整数像素密度、Playwright 与 Chromium 版本。`tools/render-sync-svg.cjs` 将原始字节作为浏览器图片渲染，保留中文字体回退；SVG 脚本不执行，外部资源请求全部阻止。`--prepare` 从固定原文独立重建，先校验完整 PNG 的哈希再更新缓存；原文、字体效果、渲染器或像素改变时须重新复核。渲染结果、原谱音符及光学节奏仍逐项绑定，所有音频定位限值保持。可用 `PLAYWRIGHT_BROWSERS_PATH=<浏览器目录> node tests/browser-svg-reference.cjs` 检查真实渲染的重复性、尺寸、原文保留、离线资源及版本失败保护。

机器复核记录位于 [sync-bulk-evidence](sync-bulk-evidence/)。`reviewed: true` 是播放器启用标记，不表示已完成逐曲人工试听，也不把两种算法相近当作实测歌词误差。各曲的完整原始素材、时间点和检查依据均可追溯。

批次 01 已通过素材哈希、时间范围、同步结构与 JS/Python 单元测试。实际 PHP 播放页完成 7 个音轨、三种视口下的 252 个区域位置检查与 75 次关键跳转，等待动画完成后核对，无页面脚本错误；结果见 [浏览器记录](sync-bulk-evidence/batch-01-browser.json)。原有 8 份同步文件字节不变。

## MIDI 参考与扫描识别修订

单段正文不超过四行、每段只需一个阅读区域的文字歌，可使用已经核对同名的 MIDI 参考定位各段起点。已用《与我同住》《主你启示一个奥秘》《祂不误事因祂是神》《只要信祂》等曲核对；参考链接和固定 SHA-256 见 `tools/sync-midi-references.json`，来源为[圣徒诗歌目录](https://chinatownministry.org/Hymns.php)。参考文件缓存到 `CACHE/midi/`，不自动下载。 多个正文阅读区域须额外提供逐段起句与已核对的 MIDI 音符起点，每个起点至少核验五个旋律音，不使用区域长度推算。《像长江大河》的分句另核对公开 MusicXML：44 个主歌音符加 22 个副歌音符与参考 MIDI 全部一致，副歌从第 44 号起音开始；和声、旋律模板须独立确认每段的每个阅读区域。程序按实际 MIDI 速度变化构建和声、主旋律两组模板，在每段实际音频中独立匹配，再核对调性、起点、相位、匹配代价和乐段长度；不以音符数推算字词时间，不声称歌词在 MP3 第 0 秒起唱。

```sh
python tools/midi-sync.py --cache sync-drafts/bulk --songs 01-362 01-421 01-429
```

扫描图识别现支持更严格的投影分行、无标点段号和“我来”等短歌词行；已在原先缺行的《主寻亡羊歌》《我来就主歌》《信徒精兵歌》等曲中重新核对完整段落。音符匹配补充升降号、附点、八分/十六分音符线及延音线的像素检查。新增阅读区域后必须重做完整时间轴匹配，禁止沿用截断的旧时间点。已提交的原始图片和文字不修改，最初确认的 8 份同步文件继续保留。

识别器第 5 版在明确报出缺少某段歌词时，只在该谱行歌词范围内重新检查稀疏行，并裁去左右空白后识别短句；完整谱行数和段数必须保持一致才采纳。原先正确的谱行不重分区域。已用《活出基督歌》末尾“为你发光”等四行验证：前 13 个识别行保持一致，恢复后为四段、每段三行，完整时间轴重新通过音乐检查。恢复的文字、范围与置信度保留在 `sparseRowRecovery` 中。

图片歌曲若另一音轨未通过录音之间的对应检查，可对该录音单独运行同一谱面的双节奏模板匹配，继续使用相同的代价、调性区分和反复检查。独立时间轴按实际完整演奏段数生成；阅读区域必须与主版本完全一致，每个时间点仍须递增且在该音轨时长内。独立匹配不合格的版本继续待校准，不使用另一录音的段数强行套用。对应指标与原录音映射失败原因保存在复核记录的 `recordingScores` 和 `recordingMapFallbacks` 中。

图片也可使用已经核对同曲的 MIDI 参考，配置见 `tools/sync-midi-image-references.json`。先将完整简谱音符序列与 MIDI 高声部起音对齐，要求编辑代价不超过 12%、调性有明确区分，而且所有最优对齐路径中的每个谱行起点都落在同一个 0.1 秒区间内；不会以字符数或音符数估算歌词时间。再对每个实际录音的每段分别匹配 MIDI 和声、旋律两组模板：每一行起点须相差不超过 0.5 秒，匹配代价、调性区分、完整乐段长度和各段相位均须通过原有严格检查。原来的双节奏模板失败记录保留，新的独立参考依据另记于 `.midi.json`。此方法已用于《普世欢腾歌》和《同声欢呼歌》，参考来自同一[圣徒诗歌目录](https://chinatownministry.org/Hymns.php)。

```sh

```

## 音频检索同曲参考

`tools/find-midi-references.py` 把已缓存公开 MIDI 的完整和声与目标录音实测的重复乐段重采样为 512 帧，通过循环相关检索全部移调和相位，输出 `reference/audio-midi-suggestions.json`。它只提出参考候选，不写时间轴；循环相位不能直接作为歌词起点。同曲填词或不同译文也不冒充逐字识别。检索对照曲《金琴在天响起》《靠近主》《像长江大河》均返回已验证的 MIDI 第一名；随机音序测试另覆盖已知移调及相位变化。

## 人声转写与实际顺序

人声录音可先运行 `transcribe`，再用 `tools/align-transcript-sync.py --cache CACHE --songs ID...` 核对实际演唱顺序。正文每个阅读区域都必须有转写对应，并至少通过两个相互一致的上下文音频窗口检查；有争议时补充窗口，若出现两组不同的时间簇则继续待校准。起点核对参考转写词的实际时间区间；遇到转写从延音词中部才开始计时的情况，还要求两个窗口的同一首词有有效时长、置信度合格且词尾与转写相符；结尾回唱会复用原来的阅读区域。重复副歌使用编辑距离对齐，避免把两次副歌拼接成一次。单独标注在分隔线后的专辑署名不当作演唱正文，原 TXT 保持不变。没有覆盖完整正文或尾部顺序仍不确定时，继续标为待校准。

无乐谱的歌词图片按原图编号和副歌标记划分阅读区域，保留不连续的原段号及外语副歌。《所有美善的力量》的录音为德语，已核对实际演唱对应原图第 1、2、6 段，三次副歌复用中文副歌区域，未演唱的印刷段落保留区域但不编造时间点。明确的翻译对应见 `tools/sync-image-transcript-profiles.json`，锁定原图、音轨及完整转写的哈希；所有转写片段均须解释，简短非歌词尾语须逐项列明。`tools/align-image-transcript-sync.py` 对原语言起点使用与文字歌曲完全相同的双窗口及延音检查，不以中文译文冒充德语字词识别。此配置仍须通过声学匹配和浏览器检查，配置存在本身不代表已经发布。

```sh
python tools/align-image-transcript-sync.py --cache sync-drafts/bulk --songs 06-002 --threads 1
```

首词落在音频窗口左边缘时，可显式添加 `--ctc-model-dir sync-drafts/models/mms-fa` 作独立核对。使用固定版本的 [MMS_FA ONNX 模型](https://huggingface.co/xycld/lyric-align-mms-fa)，版本、模型与词表 SHA-256 均由 `tools/sync_batch_ctc.py` 锁定。该分支不向 CTC 模型提供目标文字，而是在自由解码输出中查找完整首词及下一词的起音；首词至少三个字母，每个匹配字母的概率须不低于 0.2，平均不低于 0.5。两个不同窗口须各自只有一个候选、起点相差不超过 0.5 秒，且落在原转写首词区间内；CTC 词尾及下一词起音均须与 Whisper 首词词尾相差不超过 0.5 秒。原窗口仍须确认同一首词及词尾，其他有效窗口如有冲突则拒绝，所有后续区域继续使用原双窗口规则。它不能补造漏唱或漏识别的首词，也不能替代完整正文顺序核对。

模型使用 CPU ONNX Runtime，按实际窗口作零均值及单位方差归一化；MMS 附加的常量通配符不参与自由解码。声学输出按模型、音频哈希、窗口和预处理参数缓存；原始失败窗口、独立字符起点及概率均随复核记录保存。模型只用于离线制作，不进入网站发布文件，也不自动下载。`06-002` 的首词在两个窗口中均为 14.586 秒，导出起点 14.59 秒；该例仍须完成浏览器位置验证。

```sh
python tools/align-image-transcript-sync.py --cache sync-drafts/bulk --songs 06-002 \
    --ctc-model-dir sync-drafts/models/mms-fa
```

```sh
    --model-dir sync-drafts/models --songs 01-040 --workers 1 --threads 2
python tools/batch-sync.py --stage align --kind text --cache sync-drafts/bulk \
    --model-dir sync-drafts/models --workers 2 --threads 2
python tools/batch-sync.py --stage score --cache sync-drafts/bulk \
    --songs 05-001 05-002 --workers 1 --threads 1
python tools/batch-sync.py --stage publish --cache sync-drafts/bulk \
    --songs 05-020 05-023
python tools/batch-sync.py --stage report --cache sync-drafts/bulk
```

模型必须已缓存，程序不自动下载模型。`transcribe` 阶段可额外生成普通语音转写供诊断，不是发布条件。原图、MP3 和 TXT 不修改；已有同步文件自动跳过。缓存保存原素材 SHA-256，素材变化后重新计算。候选写入缓存的 `ready/`；`publish` 仅接收显式指定的本批曲目，核对当前素材及全部音轨，再将候选和复核记录放入仓库，拒绝覆盖已有文件。随后运行同步校验和浏览器位置检查，通过后提交推送。`report` 更新全库进度，包括待校准及待音轨匹配的曲目。

`--retry` 可重试失败候选，优先复用已保存的音频窗口。只有至少两个独立窗口组已确认相同音乐相位、重复音乐足够相似，且冲突候选中有一个得到相位佐证时，才丢弃冲突窗口；无声学依据的边界不靠音乐相位补造。

音频窗口按原素材哈希、演唱顺序、语言及窗口参数保存断点；每完成一组即写入缓存。任务中断后重启同一命令，已完成的匹配窗口不会重复计算。`--kind text` 或 `--kind image` 可限定处理形式。

`transcribe` 也按模型实际解码窗口保存到 `asr-windows/`。只有进入下一窗口才将上一窗口的全部片段写为完成断点；中断时的半个窗口会重算，完整转写才进入 `asr/`，不把部分结果当成整首已完成。续跑核对音频哈希和模型，保留已识别语言，从原音频的实际窗口位置继续，不拼接或缩放时间戳。回归测试覆盖中途退出、重放半窗口和避免重复片段。

文字候选的主录音已通过、另一录音的音乐映射未通过时，可运行 `--stage align-tracks`，为待处理录音独立执行原有歌词双窗口和重复音乐检查。每个录音使用按音频哈希区分的窗口缓存，避免复用主录音的声学窗口；素材和录音哈希必须与候选一致。成功依据附入原复核记录的 `recordingAcoustics`，原主录音时间点保留。此阶段仅处理尚未发布的普通歌词匹配候选，不修改已经发布的数据。

```sh
python tools/batch-sync.py --stage align-tracks --cache sync-drafts/bulk \
    --songs 03-026 03-029 04-002 --workers 1 --threads 2 --retry
```
